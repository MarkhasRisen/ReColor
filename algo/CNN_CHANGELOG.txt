VERSION 5 — CIELAB Rework + Munsell References (Feb 26-27, 2026)
Commits: 59b68237, ccc7f271
File:    algo/cnn.ipynb
───────────────────────────────────────────────────────────────────
MAJOR REWORK — replaced entire labeling system:

Labeling changes:
- REMOVED: all hard-coded HSV thresholds
- ADDED: CIELAB color space nearest-neighbor classification
- ADDED: Munsell-sourced reference colors for each class:
    Class 0 Neutral  — chroma threshold (C* < 22)
    Class 1 Red      — Munsell 5R  5/14  → sRGB (220, 38, 38)
    Class 2 Orange   — Munsell 5YR 6/14  → sRGB (249,115, 22)
    Class 3 Yellow   — Munsell 5Y  8/12  → sRGB (234,179,  8)
    Class 4 Green    — Munsell 5G  5/10  → sRGB ( 34,140, 34)
    Class 5 Cyan     — Munsell 5BG 5/6   → sRGB (  6,182,212)
    Class 6 Blue     — Munsell 5B  4/8   → sRGB ( 37, 99,235)
    Class 7 Violet   — Munsell 5P  4/10  → sRGB (124, 58,237)
    Class 8 Pink     — Munsell 5RP 7/10  → sRGB (236, 72,153)
    Class 9 Brown    — Munsell 5YR 4/6   → sRGB (146, 64, 14)
- Uses Delta-E 1976 (Euclidean distance in Lab) for classification
- Neutral assigned when chroma C* < 22 (achromatic pixels)

Training changes:
- Dataset: 6000 CIFAR-10 train + 2000 synthetic patches + 1000 test
- Synthetic patches generated in LAB space (random hue ±30° from ref)
- Auto-computed class weights from actual frequency distribution
- Weighted loss: custom weighted_sparse_cce (handles class imbalance)
- Callbacks: ReduceLROnPlateau (factor=0.5, patience=4)
             EarlyStopping (patience=8, restore_best_weights=True)

Architecture (unchanged from mk2):
- U-Net: 32 → 64 → 128 filters (encoder)
         128 → 64 → 32 filters (decoder)
- BatchNormalization after every Conv2D
- Skip connections via Concatenate
- Output: Conv2D(10, 1x1, softmax) — per-pixel 10-class probabilities

New cells added:
- Cell 1.5: "Load Saved Model" — skip retraining, load from
  color_segmenter.keras with custom_objects
- Cell 2: Updated visualization — 4 panels:
  Input | CIELAB Ground Truth | CNN Prediction | 50/50 Overlay
- Cell 3: TFLite INT8 export (unchanged, already working)

Model files:
- color_segmenter.keras — full Keras model (~2-3 MB)
- color_model.tflite    — INT8 quantized for mobile (~500 KB)

VERSION 6 — CNN 256×256 + Tile-Based Pipeline (Apr 13, 2026)
Files: App.js, tensorHelper.js
───────────────────────────────────────────────────────────────────
MAJOR PIPELINE REWORK — removed real-time loop, added tile-based
full-resolution processing:

CNN changes:
- CNN_SIZE upgraded from 128 to 256 (higher per-tile detail)
- Model still uses same U-Net architecture and INT8 quantized
  TFLite file (color_model.tflite)

Pipeline changes (CameraSimScreen):
- REMOVED: real-time frame processing loop (takePhoto every 100ms)
- ADDED: freeze-and-process workflow:
  1. Live camera preview (no CNN processing)
  2. User presses Freeze button to capture full-res photo
  3. Full-resolution image tiled into 256×256 patches
     - Grid: ceil(width/256) × ceil(height/256) tiles
     - Edge tiles zero-padded (black) to fill 256×256
     - e.g., 4032×3024 = 16×12 = 192 tiles
  4. Each tile fed through CNN individually
  5. Tile masks stitched back into single full-res class mask
     - Only valid region copied (padding discarded)
  6. applyCVDSimulation() runs on full-res image + full-res mask
  7. Result displayed as frozen overlay

- ADDED: mask caching — CNN mask + decoded image cached in refs
  - Switching CVD type (Protan/Deutan/Tritan) re-applies simulation
    instantly from cached mask — NO CNN re-run needed
  - CNN only runs once per capture

- ADDED: progress indicator ("Processing tile 12/40...")
- ADDED: UI yields to render thread every 4 tiles (setTimeout(0))

UI changes:
- Live mode: camera flip | freeze (snowflake icon) | gallery
- Frozen mode: reset (refresh) | — | save to gallery (download)
- Top-left: back arrow (live) → X close (frozen)
- CVD type buttons dimmed during processing
- Full-screen processing overlay with ActivityIndicator

CameraSimScreen purpose clarified:
- CameraSimScreen = CVD SIMULATION (shows what colorblind see)
- Camera Enhance (future) = DALTONIZATION (color correction)
- Previously CameraSimScreen was incorrectly calling
  applyDaltonization() — fixed to applyCVDSimulation()
- ModeSelector label corrected: "Enhancement" → "Simulation"

Stability fixes:
- ADDED: ScreenErrorBoundary wrapping CameraSimScreen
  - Catches native module init crashes (e.g., TFLite failure)
  - Shows "This screen crashed" UI with error + Go Back button
- ADDED: AppLog file-based debug logger
  - Writes to recolor_debug.log on device filesystem
  - Logs: mount, permission, tflite state, pipeline errors
  - Viewable from Settings > Debug Logs (works offline)
- ADDED: guards in applyCVDSimulation/applyDaltonization for
  invalid cvdType (returns unmodified pixels instead of crash)
- ModeSelector navigation: 120ms delay before replace() to let
  VisionCamera release before screen teardown
